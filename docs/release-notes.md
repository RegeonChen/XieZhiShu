# 志书撰写工具 v0.4.0

> 本次的核心变化：**网页材料与本地索引的准备工作，从"每次生成时临时跑"改成"先建好、再生成"**。设置页新增「建立缓存与索引」，一次把网页正文缓存与本地资料库索引建好（带进度与预计剩余时间）；**资料没备齐就点生成会被明确拦住**并引导去建立——这是刻意的严格设计（用户裁定），不是故障。
> 另一个大变化：站点文章清单的发现规模**由算法自己决定**（逐层走列表页，走到"再走也没有新文章"为止），不再固定 20 页 / 2 层。真实站实测：长乐新闻网多发现 **2,947 篇**、新注册的长乐区人民政府目录 **183 → 726 篇**。
> 抓取可**暂停/继续**，中断（关软件、关机）后可**接着跑**；**已建立的不重复建立**；资料删除时对应缓存/索引**同步删除**。
> **安装包**：`XieZhiShu-Setup-0.4.0-x64.exe`（Windows x64，NSIS，**含本地嵌入模型 BGE-small-zh-v1.5**；未签名，安装时如提示"未知发布者"请选择"仍要运行"）。

## 一、建立缓存与索引（新的准备工作流程）

设置页原「本地检索索引」改为「**建立缓存与索引**」，点一次「建立」= 为**网页正文缓存**（按年份区间，默认 2005–2025，可改）与**本地资料库索引**建好缓存/索引。

- **生成前严格闸门**：本次生成要用到的材料只要还有未建立的，就会在点「生成汇编」时**直接拦住**，列出缺口并给出唯一出口「去设置页建立」；**主进程会再查一次**，所以绕过界面或中途改主意都拦得住；拒绝发生在写任务数据之前（不会留下半截任务）。这是刻意的严格口径：**建完才能生成**。
- **已建立的不重复建立**：进度条上的"本次要建 N 篇"就是真正要干活的篇数，已建好的如实报"直接跳过"。
- **"试过但没有正文"与"越权地址"都留标记、且不算缺口**：否则闸门会因为几篇永远建不了的文章永远不放行（这是本功能最大的坑）。
- **建立引擎**：本地索引**先排队、与网页抓取并行**（网络与 CPU 不互相抢），停止用独立开关，同一时刻只允许一个抓取在跑；收尾用最终结果覆盖进度快照（进度不会"停在 5 篇前"）。
- **删除一致性**：删站点 → 级联删该站缓存；删目录行 → 触发器**自动**删对应缓存（Migration 051，不依赖"记得一起删"）；建立开始时与删站点后各跑一次孤儿缓存清扫。反向不补偿：缓存删了但目录还在 = 回到"待建立"，正是要的语义。

## 二、站点文章清单：发现规模自动决定

“这个站点有哪些文章”原来用固定 20 页 / 2 层抓列表页兜底。实测这个固定值**不只是在保守，而是在饿着老站点**：长乐新闻网既无 RSS 也无 sitemap，它的 6.2 万条目录来自一次深层发现，之后每次同步只能新增几十条。

- **改成"收益饱和"停止**：连续多页既没有新文章、也没有新的"年-月"格子就自然收工；年-月归档页优先于年、索引、翻页；并按**本次实测哪种页面在下蛋**自动调整先后；目标区间里还没发现任何文章的年份强优先。
- **安全阀 300 页 / 6 层 / 3 分钟**：撞到会**如实说"还有 N 个列表页没走完"**，绝不假装抓全；被层数上限剪掉的深层链接也计数上报。
- **页/层数是算法的输出，不是让您填的参数**：实测用量记回站点行，下次当**起点下限**（一次偶发失败不会让发现范围一次比一次小）；设置页「站点清单发现」默认**自动**，只有撞安全阀后想放开时才切手动。网页资料库面板每个站点会显示「**实测发现 36 页 / 2 层**」这类字样。
- **重复同步很省**：目录已建全时几页内即收工。
- 实测对比（同一站点、同一时刻）：长乐新闻网 旧 20 页 → 撞上限、新增 2,238 篇；新自适应 → **36 页饱和、新增 5,185 篇**（14 秒）。长乐区人民政府 旧 20 页 → 183 篇（还有 227 个列表页没走）；新 → **115 页饱和、726 篇**（14 秒）。

## 三、网页资料库 2.0（抓取链路加固）

- **只按发布时间筛**：第一步筛选只看发布时间，不掺 `lastmod`；日期阶梯 **L1→L5**（RSS/Atom → sitemap（news 扩展优先）→ URL 内嵌日期 → HTTP `Last-Modified` → 页面内日期），推不出宁可留空。
- **不设总量上限**：通过闸门的材料**全部**进入细读与提取（此前的"抓取上限 + 按标题排序"会把标题不含主题词、正文却切题的文章静默排除）。
- **抓取提速与抗限流**：档位（保守 120ms/2、标准 60ms/4、快速 40ms/6，遵循站点 `robots` 的 `Crawl-delay`）；出现限流/连续失败自动降档并**重抓本轮失败篇**（降档只对本次运行有效，不改您的设置）。
- **正文缓存**：站点级跨任务复用，命中即本地重筛、零网络；只抓正文、不做主题筛选、不写任务账本。
- **暂停 / 继续 / 中断续跑**：暂停期间不发新请求、保留账本与缓存，继续时从原处接着跑；关软件即终止（不留后台请求）。

## 四、“无可用正文”到底是什么（实测澄清）

您在这次试用里看到大量「无可用正文」标记，我做了逐条定位：**不是缺陷**。以 2013 年为例，长乐新闻网那批老文章的 URL 现在**被站点重定向到首页**（实测 6/6 个 URL 在 3.5 秒间隔下重试、改 https 也一样，返回的都是首页 HTML），A1 探针判定"这页不是这篇文章"→ 记 `no-body`。这类标记**必须留**，否则闸门会被这 1,000 多篇永远建不了的文章卡住。同站同年仍有 946 篇正常抓到。

## 五、其他修复

- **建立缓存不再写任务账本**（真机自检抓到的崩溃）：建立时没有任务，任何写账本的路径都会命中外键，整次建立变成 `FOREIGN KEY constraint failed`；现在按模式分流并加了两层兜底（账本只作诊断，不能因一条诊断打崩整次建立）。
- **注册站点后自动同步清单** + 面板每个站点显示「清单 N 条 / 正在同步 / 同步失败原因」+「同步清单」重试按钮（此前注册后毫无反应，建立也完全看不到这个站）。
- **站点行布局**：新增按钮后窄栏里会把站点信息挤成"一列一个字"，已改为整排换行。
- **界面文案**：设置页与引擎提示里此前会字面显示 `**` 记号，已清理（界面是纯文本渲染）。

## 六、数据结构变更（自动迁移）

迁移账本 **001 → 052**，启动时自动执行、**不可回退**。本次新增：

- **045/046**：网页资料发布时间阶梯结果（`published_date` / `date_source` / `date_confidence` / `url_date` / `sitemap_lastmod` / `http_last_modified` 等）与存量回填（只填空值，不覆盖已有 feed/sitemap 结果）。
- **047**：按任务的全量抓取账本 `task_web_fetch` + 任务的网页年份区间列（账本**只作诊断**，不再作为"已处理"的跳过依据）。
- **049**：站点级正文缓存 `web_article_body`（跨任务复用，含"正文可用/无可用正文/越权地址"三态之外的哈希与探针结论）。
- **050**：缓存"尝试结论"三态 `state`（`ok` / `no-body` / `blocked`）——闸门据此区分"还要建"与"永远建不了"。
- **051**：触发器 `trg_web_article_body_follow_catalog`——删目录行时自动删对应缓存行（任何新增的单行删除都不会留下孤儿缓存）。
- **052**：`web_sites` 增加站点发现的实测规模三列（`discovery_pages` / `discovery_depth` / `discovery_at`）。
- 048（候选排队表）已废弃不用，按惯例保留不删。

## 八、安装与升级

1. 运行 `XieZhiShu-Setup-0.4.0-x64.exe`（未签名，Windows 可能提示"未知发布者"）。
2. **覆盖安装即保留原有数据**（数据库在 `%APPDATA%\xie-zhishu`）；首次启动自动执行迁移。
3. **升级后第一次生成前，请先到 设置 →「建立缓存与索引」点一次「建立」**：软件会按您的年份区间把网页正文缓存与本地索引补齐（可随时停止、可关软件后接着跑）。未建齐时点生成会被拦住并引导过去——这是本次的刻意设计。
4. 建议同时确认网页资料库里各站点的「清单 N 条 / 实测发现 N 页」是否正常（新站点请点一次「同步清单」）。

## 九、已知限制（如实说明）

- **站点发现不做"全站归档枚举"**：撞安全阀（300 页/6 层/3 分钟）时会明确提示"还有列表页没走完"，需要更全可在设置页切手动并调高页数/层数。
- **「无可用正文」标记目前是"永不再试"**：老文章被站点删除后重试无意义，但如果某站点只是**临时**返回模板页，那些篇会被永久写掉。可加一个「重试无法建立」按钮（只清 `no-body` 标记、保留好正文），待定。
- **两次生成前必须建齐**：这是本次刻意的严格口径；如果您希望有"临时放过"的逃生门，需要改裁定。
- **网页抓取依赖真实环境**（站点结构、反爬、限流）；老文章被站点删除后**无法取回**（按信源白名单原则，工具不会换渠道去取）。
- **安装包未做代码签名**（首次运行需手动允许）；本地向量模型不可用时自动降级为纯词法检索。
- **本版本的安装包是本地构建的**（含 90 MB 本地嵌入模型）。⚠ 请勿重复推送 `v0.4.0` 这个 tag：CI 打出的安装包**不含本地模型**，会把本 Release 的资产覆盖成降级版本。
