# 志书撰写工具 v0.3.0

> 本次是**Phase 7「生成汇编」重构成型以来的首次大版本发布**：汇编从"资料卡片"变成"连续志稿文档"，并围绕它把网页资料库、检索索引、人机协同编辑三条链路打通与加固。
> 相较 v0.2.1，网页材料的相关性、可追溯性与正文质量都有实质提升，也修掉了若干会**静默出错**的老问题（错年、索引全库失效、模板页当正文）。
> **安装包**：`XieZhiShu-Setup-0.3.0-x64.exe`（Windows x64，NSIS；未签名，安装时如提示"未知发布者"请选择"仍要运行"）。

---

## 一、Phase 7.1–7.2：汇编数据模型与生成管线重构

- **汇编 = 一篇连续志稿文档**（不再是卡片列表）：Migration 030 新增段落元数据 9 列（结构化时间 `year/month/day`、时间可信度、来源编号、证据引文 `evidence`、origin、revision、kind）+ 三张新表（汇编来源编号表、版本历史、汇编级对话）；Migration 031 回填既有汇编（零丢失，真实库演练：无编号段 0、有年份段 611、时间待核 35）。
- **生成管线合并为三步**：`AI 分窗细读（只筛选）→ 整合提取（裁剪 + 补全 + 整合）→ 矛盾扫描`，取代旧的「提纯 + 修正」两趟。
- **三道本地硬校验**（防幻觉、宁降级不丢料）：证据必须逐字可回查、正文数字必须在该来源原文中找得到（整 token 口径）、时间可信度本地判定；任一不过就把该段**降级保留原文**。
- **成文阶段去重**：同一来源近似重复且数字一致才合并；**数字不一致一律两段都留**（交给矛盾扫描，绝不抹平矛盾）。跨来源近似重复（网页转载/网站版与工作区同文档）用更严阈值（0.92）且只在数字一致时合并。

## 二、Phase 7.3–7.5：连续文档查看器 + 版本差异 + 与文档对话

- **连续文档查看器**：段首时间徽标 + 正文 + **段尾来源圆标**（圆标 = 本汇编内首次引用顺序 1..N，可点击查看该来源在本汇编的全部段落与原文），按年份分节；工具栏统计「N 段 / N 篇来源 / N 段时间待核」。
- **改动自动复核**：对话改完立即给出**本次修改前后**的段级差异（新增/修改/删除 + 字级高亮），只提供「采纳 / 回退」两个出口（回退不产生新版本）。
- **悬浮对话面板**（软件内改动汇编的唯一入口）：可拖动/最小化，历史气泡 + Ctrl/⌘+Enter；模型以 8 种 op（delete/replace/insertAfter/move/merge/split/setTime/replaceAll）引用**段 id** 修改文档，本地逐条校验（段号存在、来源编号合法、数字有据、merge 仅同来源、不得删空整篇）。
- **改完时间自动重排**：对话里改了时间标签会在同一次操作内按时间重排（纯"调序"指令不触发，避免覆盖用户意图）。
- **用户点名改数字时豁免数字校验**（`allowNewNumbers`）：只有用户明确给出数值才允许新增，绝不给推测开口子。

## 三、网页资料库并入修志流程（三批）

**第一批（年份与索引）**
- **年份兜底按来源分流**（修静默错年）：年鉴/年报类标题 → 年份 −1；其它标题年份 → 原样采用；网页无标题年份 → 用**发布时间**；都推不出 → 保持「时间待核」。
- 发布时间落库（Migration 037）：网页发布时间不再只存站点清单表，抓成来源时一并写入并按 URL 回填。
- **网页资料进向量索引**（此前完全漏掉）：抓取即入队，生成前等待就绪（预算 120s），否则保守闸门的"语义兜底"对网页从未生效。

**第二批（材料量可控 + 抓取上限）**
- 跨来源近似重复合并；抓取上限（篇数/字数）+ 汇总如实告知「标题命中 N 篇，实际采用 M 篇，另 K 篇因上限未采用」；未配置大模型时**跳过抓取**并改用闸门收窄后的材料（不再白等十分钟）。

**第三批（材料集合落定 + 溯源 + 伪矛盾收敛）**
- **网页材料集合在首次生成时落定**：重新生成默认复用同一批（可复现、版本差异干净）；站点新命中文章只报数量。
- **来源本地快照**：只读库里已存正文（不联网），卡片显示「抓取于 …」，快照弹窗按本次检索词高亮命中片段；正文过短会标注可信度存疑。
- **伪矛盾收敛**：矛盾扫描提示词新增「以下情形不算矛盾」清单（不同年份、不同统计口径、规划/在建/投用阶段差异、上位与下位范围差异），并要求利用时间字段；矛盾说法行显示时间。
- **网页材料集合自此只由生成管线管理**：面板只读显示「本任务已锁定 N 篇」。

## 四、真实数据暴露并修复的三个「静默错误」

1. **抓取上限 + 排序口径失效**（导致网页段落 77 → 4 段）
   - 现象：同一主题重跑只得 99 段（前一轮 125 段），**网页段落 77 → 4**、本地文件 48 → 95；缺失的 108 段里 69 段来自网页，全部切题（滨海新城福州三中滨海校区、融侨赛德伯学校高中部、长乐三中恢复高中办学、长乐五中申报省级达标校、2017—2020 高中布局整合计划…）。
   - 根因一：抓取上限 80 篇把 477 篇压到 80 篇，**两轮重合 0 篇**，切题网页正文从 94.1 万字掉到 9.4 万字。
   - 根因二：**筛选用 bigram、排序用完整子串**，而检索词是长词/空格拼接的关键词串 → 477 篇与 80 篇标题打分**全部 0 分**，排序退化为"按清单顺序截取"。
   - 修复：`extractTopicTerms` 对空格拼接的关键词列表逐词取词；排序改为与筛选一致的 bigram 重叠计数 + 完整词加权；上限 80 → **300 篇 / 150 万字**。
   - **须知**：上限仍小于候选数（同一主题 495–3,293 篇）时，标题排序必然排除"标题不含主题词、正文却切题"的文章——相关性取舍最终靠**正文**（正文精过滤 + 保守闸门 + 细读窗口）。

2. **网页正文抓取质量**（本轮新修，用得就是您举的例子）
   - 现象：段落实为文章标题（「长乐新添一所普通高中，将于9月开学。」），正文里的校名/规模/投资/地点全丢；且被标了一个正文中查不到的年份。
   - 根因一（抓取层）：站点对**已失效的老文章 URL 返回 HTTP 200 + 通用模板页**。实测 3 个 2014–2016 的 URL 现在都返回**同一份 128,054 字节模板页**，正文里连文章标题都没有；此前只看状态码，就把整页模板文本当正文入库——最新任务 208 篇里 **119 篇（57.2%）**、全库 685 篇里 **178 篇（26%）**，且这 119 篇正文完全相同（同一 hash、7,024 字），还吃掉 **56% 的抓取预算**。
   - 根因二（过滤层）：正文精过滤把标题拼进匹配文本 → "标题命中即可入库"。
   - 根因三（生成层）：段落缺"必须有正文信息量"与"时间必须有据"的硬校验，全库 380 段**全部**标 `time_confidence=exact`。
   - 修复：**A1** 正文有效性校验（标题核心片段必须出现在提取正文或原始 HTML 里，否则判"未取到正文"丢弃、不入库不索引，并在生成汇总报数）；**A2** 正文清洗（去导航/面包屑/推荐列表/页脚）+ 记录正文来源；**C1** 拒收"只复述标题"的段落（含降级路径）；**C2** 年份必须在正文里或来自年鉴 −1/标题/发布时间，否则标「时间待核」；**D** 提示词要求"不得复述标题、每段必须给出正文具体要素（主体/规模/金额/地点/时间），允许压缩但不许丢要素"。
   - **须知**：2012–2016 的老文章在该站点**服务端已经失效**，无法取回（按信源白名单原则，工具不会换渠道去取）。现在的行为是"不再拿模板页冒充正文"。

3. **向量索引全库失效**（`chunk_embeddings` 为 0、所有来源 `index_state='failed'`）
   - 根因：`onnxruntime-node`（file: 依赖 `vendor/onnxruntime-node-stub`）的 node_modules 目录是空的 → transformers 的 node 构建 import 失败 → 每次 `pipeline()` 抛错。**不是模型缺失**（94 MB `model.onnx` 一直在）。
   - 修复：重新物化依赖 + Migration 038 落库失败原因（`sources.index_error`）+ 设置页新增「本地检索索引」区块（状态/失败数/最近失败原因/重建索引 + 继续重建）。
   - **索引重建提速与可续跑**：进度持久化（跨页面切换、跨软件重启都可见）、只重建未就绪的来源、被强杀后从断点继续且百分比单调前进；单块耗时 **133 ms → 17 ms**（按长度排序分组消除 padding + WASM 多线程 1→8，Worker 失败自动回落并在状态里如实显示）。实测 6 篇真实网页资料（249 分块）**4.1 秒**跑完（此前同规模 100 秒）。

## 五、其他改进与修复

- **导出命名**：`<当前任务标题>-资料汇编.docx` / `.xzsc`（任务重命名后导出即用新名字）。
- **「重新生成汇编」入口**：此前软件里**没有**这个按钮（只有首稿能重新生成），已有汇编的任务只能新建任务重跑；现在悬浮面板底部新增该按钮 + 二次确认（网页材料沿用已锁定的一批，不重新抓取）。
- **下线两个会误导的入口**：「重新检索网页材料」（先清空再抓取的非原子动作，且因检索词是 7 字长词必然 0 篇落库）与「纳入新材料」（同一缺陷）。今后材料集合只由生成管线管理。
- **正文抓取器与列表页识别**：RSS/Atom → sitemap → BFS 发现顺序、条件请求（ETag/Last-Modified）、robots 礼貌限速、正文提取器保留表格、发布时间解析（含"日期最后一位被截断"的回归修复）。

## 八、安装与升级

1. 下载 `XieZhiShu-Setup-0.3.0-x64.exe` 并运行（未签名，Windows 可能提示"未知发布者"）。
2. 覆盖安装即保留原有数据（数据库位于 `%APPDATA%\xie-zhishu`）；首次启动会自动执行迁移与存量清理。
3. 建议启动后进入 **设置 →「本地检索索引」**：确认「已索引 / 共 N 篇」接近全量；若显示失败或未就绪，点「重建索引」（可后台进行，进度跨重启可见）。
4. 建议用**新任务**跑一轮完整流程（生成汇编 → 审阅 → 生成初稿）以体验新管线；已有任务的汇编如需按新规则重做，用面板底部的「重新生成汇编」。

## 九、已知限制

- 抓取上限 300 篇 / 150 万字：候选更多时按标题相关度取舍，**标题不含主题词的"建校/扩建"类文章仍可能被排在门外**；如需更高覆盖，可提高上限（首次生成约 6–10 分钟，之后重新生成复用已锁定材料，不再重复抓取）。
- 老文章（该站点 2012–2016）服务端已失效，无法取回。
- 「网页正文精过滤只看正文 + 放宽 12,000 字窗口」尚未实施（本轮 A1 已挡住最主要危害）。
- 本地向量模型不可用时自动降级为纯词法检索（功能可用，召回略降）。
