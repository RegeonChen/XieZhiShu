# 志书撰写工具（XieZhiShu）

AI 辅助地方志 / 志书编纂的 Windows 桌面工具。面向地方志、党史方志办公室的修志业务，把大模型能力嵌入到**资料收集、整理归纳、资料汇编**环节，全程「依靠不依赖、赋能不替代」——史料考证、矛盾裁定、终审定稿始终由人工主导。

> ## ⚠️ 功能现状（重要）
>
> **目前仅实现到「生成汇编」功能区，「撰写初稿」功能尚未实现。**
>
> 也就是说：本工具当前能帮您完成 **资料收集 → 整理归纳 → 生成并审阅资料汇编 → 导出汇编** 这一段；从资料汇编到**志书初稿**的撰写环节仍在开发中，请勿把当前版本用于正式初稿撰写。
> 左侧导航中的「撰写初稿」入口已**置灰并标注「开发中」**（点不动），新手引导也不会把您带到那里。

---

## 一、产品定位与原则

| 原则 | 含义 |
|---|---|
| **本地优先** | 全部用户数据（资料、汇编、索引）保存在本地 SQLite 与本地文件系统；不需要账号、不依赖自有云服务。只有「调用您自己配置的大模型」与「访问您自己登记的信源网址」两类对外交互。 |
| **信源白名单** | AI 只使用您导入的文件与您登记的网站，**绝不自行从其它渠道获取信息**，也不编造出处。 |
| **全程可溯源** | 汇编的每个段落都带来源编号与证据引文，可回溯到原文（PDF 到页、Word/WPS 到段）。 |
| **人机协同** | 矛盾裁定、文段修改、终审定稿由人工主导；AI 只做筛选、提取与提示。 |
| **不花冤枉额度** | 资料解析、分块、向量嵌入、索引、缓存、抓取、矛盾检测以外的本地工作**全部本地完成**；嵌入模型随安装包分发，不联网下载、不消耗大模型额度。 |

## 二、下载与安装

最新版本：**v0.4.0** → [Releases](https://github.com/RegeonChen/XieZhiShu/releases/latest)

- 安装包：`XieZhiShu-Setup-0.4.0-x64.exe`（Windows x64，NSIS，约 340 MB，**已内含本地嵌入模型**，开箱即可用语义检索）。
- 安装包**未做代码签名**：首次运行 Windows 可能提示"未知发布者"，选择"仍要运行"即可。
- **覆盖安装即保留原有数据**（数据库在 `%APPDATA%\xie-zhishu`）；首次启动会自动执行数据库迁移。
- **升级后或首次使用，请先到 设置 →「建立缓存与索引」点一次「建立」**：软件会按您的年份区间把网页正文缓存与本地索引补齐。未建齐时点「生成汇编」会被**明确拦住**并引导过去（这是刻意的设计，不是故障）。

## 三、当前可用的功能

### 1. 资料库

**本地文件资料库**

- 指定任意本地文件夹为资料库，**双向实时同步**：新增/修改自动解析入库，移动/重命名不丢失标签与摘要，删除走系统回收站可反悔。
- 支持 PDF、Word（doc/docx）、WPS、Excel、TXT、Markdown、图片 OCR 等格式；以 `sha256 + 修改时间 + 大小` 为指纹做对账，避免重复解析。
- 标签管理与多选筛选；「整理资料」可对资料逐篇生成预处理信息（可选，不整理也能正常使用）。

**网页资料库（多站点）**

- 注册网站首页即可；**支持注册任意多个站点**，每个站点独立参与资料收集。
- **注册后自动同步文章清单**，面板显示「清单 N 条 / 正在同步 / 同步失败原因」，并可点「同步清单」手动重试。
- **站点发现规模自适应**：软件逐层走列表页，走到"再走也没有新文章"为止（收益饱和）就自然收工，不再用固定页数硬切；实测用量（如「实测发现 36 页 / 2 层」）会显示在站点行上，并记下来供下次作为起点。只有撞到安全阀（300 页 / 6 层 / 3 分钟）时才需要手动放宽。
- 抓取遵循站点 `robots`（含 `Crawl-delay`）、同域白名单与礼貌限速；支持**暂停 / 继续**，可随时停止。

### 2. 建立缓存与索引（生成前的准备）

设置页「建立缓存与索引」一次把两件事做好：

- **网页正文缓存**：按年份区间（默认 2005–2025，可改）抓取并缓存网页正文；**已有缓存跨任务复用**，命中即本地重筛、零网络。
- **本地资料库索引**：本地向量嵌入 + 词法索引，与网页抓取**并行**进行（网络与 CPU 不互相抢）。
- 全程显示进度与预计剩余时间；可随时停止；关闭软件后下次接着跑（**已建立的不重复建立**）。
- **生成前严格闸门**：本次生成要用到的材料只要还有未建立的，点「生成汇编」会被直接拦住，列出缺口并引导到此处建立（主进程会再校验一次，绕过界面也拦得住）。
- **删除一致**：删除站点或资料时，其缓存/索引**同步删除**（数据层触发器兜底，不依赖人工记得清理）。

### 3. 生成汇编（当前的核心功能区）

新建任务 → 填写撰写要求 → 指定网页资料的年份区间 → 只读预检（段数 / 字数 / 本地·网页拆分 / 窗口数 / 预计分钟）→ 生成：

1. **AI 分窗细读（只筛选）** —— 按窗口逐段判断"这段会不会写进本次主题"。
2. **整合提取** —— 每段**单一来源**（禁止跨来源拼接）、事实逐字来自原文证据、数字必须在该来源中找得到、时间必须含 4 位年份且**有据**（推不出就标「时间待核」，不猜）。
3. **矛盾扫描** —— 自动检出史实/表述冲突，以多说法对比呈现，**必须人工裁定**后才能继续。

产出与操作：

- **汇编 = 一篇连续志稿文档**（不再是卡片列表）：段首时间徽标 + 正文 + 段尾来源圆标（圆标 = 汇编内首次引用顺序 1..N，点击可查看该来源的全部段落与原文），按年份分节。
- **与文档对话修改**：用自然语言让模型改汇编，模型以 8 种操作（删/改/后插/移动/合并/拆分/改时间/全文替换）引用**段落 ID**，软件逐条本地校验（段号存在、来源编号合法、数字有据、不得跨来源合并、不得删空整篇），改完立即给出**前后差异**供「采纳 / 回退」。
- **版本与撤销**：每次修改留版本（乐观锁防并发覆盖），支持撤销/恢复。
- **导出**：`<任务标题>-资料汇编.docx` 与 `.xzsc`（可再导入）。
- **来源位置**：显示「来源位置：N/M 段（K 段有页码）」，点圆标可在右栏打开来源并定位到页/段。

### 4. 来源溯源与分栏

- 所有格式恒有「内部分栏查看」与「用外部程序打开」两种方式；内置浏览器/PDF 查看器有独立安全约束（不注入 Node 能力、弹窗与下载全拒、仅放行 http(s)）。
- PDF 按页定位（扫描件无文字层时**只跳页、不假装定位**）；Word/WPS 定位到段；老汇编如实提示"未记录来源位置"，不做检索兜底。

### 5. 设置

大模型 Provider（OpenAI 兼容，兼容 DeepSeek / 智谱等，密钥本地加密存储）、预设模型、按步骤指定默认模型、工作区资料库、建立缓存与索引、抓取节奏档位、外观主题、一键导出诊断日志（敏感字段脱敏，不含密钥）。

## 四、尚未实现 / 不在当前范围

- **「撰写初稿」功能区：尚未实现**（见文首说明）。当前版本请以「生成汇编」的产出为交付物。
- 「事件缺失补充」不在产品范围内。
- 站点发现**不做全站归档枚举**：撞安全阀时会如实提示"还有列表页没走完"，需要更全可在设置页切手动并调高上限。
- 扫描件（无文字层）**不做 OCR 定位**，只跳页。

## 五、工作原理与关键口径

| 环节 | 口径 |
|---|---|
| 网页年份筛选 | **只按发布时间**筛；日期按阶梯回退：RSS/Atom → sitemap（新闻扩展优先）→ URL 内嵌日期 → HTTP `Last-Modified` → 页面内日期；推不出宁可留空。 |
| 相关性判定 | **只看正文**（标题永不作为判据）：专指词命中，或弱指词/泛词组合命中，或与撰写要求的 bigram 相似度达标；只命中"范围词"（如地名）的一律剔除。 |
| 材料总量 | **不设总量上限**：通过闸门的材料全部进入细读与提取（只有单窗口大小可调）。 |
| 抓取礼貌 | 尊重 `robots.txt`（含 `Crawl-delay`，秒→毫秒统一换算）、同域白名单、站点级限速与并发档位；出现限流/连续失败**自动降档**并重抓本轮失败篇（降档只对本次运行有效）。 |
| 抓取账本 | 只作**诊断**，绝不作为"已处理"的跳过依据（避免新任务漏抓）。 |
| 缓存与"缺口" | "已尝试但站点给的是失效页/模板页/过短"与"越权地址"都留标记、**且不算缺口**（否则闸门会因为几篇永远建不了的文章永不放行）。 |
| 汇编身份 | 段落 ID 生成后不变；版本 = 段落数组 + Markdown 双份快照；来源编号只增不回收。 |

## 六、技术实现

### 技术栈

- **桌面框架**：Electron 43 + electron-vite
- **前端**：React 18 + TypeScript（strict）+ TipTap（ProseMirror）
- **本地存储**：better-sqlite3 13（WAL + 外键 + 嵌入式迁移框架，当前 **001–052**）
- **本地向量嵌入**：`@huggingface/transformers` + `bge-small-zh-v1.5`（ONNX），经 onnxruntime-web（WASM）在 `worker_threads` 中推理；`allowRemoteModels=false` 严格本地
- **网页正文提取**：trafilatura + `@mozilla/readability` + linkedom
- **文档解析**：pdf-parse / mammoth + word-extractor / xlsx / tesseract.js
- **打包**：electron-builder（NSIS，Windows x64）
- **测试**：Vitest（含内联单测）

### 架构说明

```
src/main       主进程：SQLite、大模型调用、资料解析与索引、网页抓取与缓存、汇编生成、日志
src/preload    contextBridge 暴露的类型安全 IPC 接口
src/renderer   React 界面（只负责呈现与交互）
src/shared     主进程/渲染进程共享的类型与 IPC 契约
```

渲染进程启用 `sandbox` + `contextIsolation`，**不暴露任何 Node 能力**；每个 IPC 都在主进程校验参数并返回统一结果类型。

### 关键实现要点

- **检索**：段落分块 + 字符 bigram 词法打分 + 本地向量余弦相似度（**过滤式精检**：达标全留，不做 Top-N 截断）。
- **生成汇编**：本地宽召回「宁多勿漏」→ AI 分窗细读 → 整合提取（三道本地硬校验：证据逐字可回查、正文数字必须在该来源原文中找得到、时间可信度本地判定；任一不过就降级保留原文）→ 矛盾扫描。
- **来源锚点**：切块时记录字符区间 → 段落一路携带 → 落锚点优先用区间映射页表（`indexOf` 仅兜底），实现"页 N = [页 N 起点, 页 N+1 起点)"的确定性页级定位。
- **工作区同步**：`sha256` 内容指纹 + `mtime/size` 映射锚点，chokidar 监听 + 防抖 + 定时兜底对账。
- **网页资料链路**：feed → sitemap → **自适应 BFS**（优先级队列 + 收益饱和停止），正文缓存站点级复用（`deflateRaw` 压缩，含"正文可用/无可用正文/越权地址"三态）。
- **迁移纪律**：所有表结构变更走迁移，破坏性迁移先在真实库副本上演练（断言版本推进、`integrity_check=ok`、外键违规 0、除迁移表外行数不变、重复执行幂等）后才发布。

### 验证基线

最新一次全量验证：**typecheck 0 错误**、**Vitest 508 / 509 通过**（唯一失败为本机 chokidar 环境项，与功能无关）、**生产构建通过**；界面改动均起真机自检（真实库副本 + 真实网络，不触碰真实数据）。

## 七、本地开发

```bash
npm install          # 安装依赖
npm run dev          # 启动 Electron + Vite 热更新
npm run typecheck    # 类型检查
npm run test         # 运行测试（Vitest）
npm run dist:win     # 构建并打包 Windows 安装包
```

> 本地嵌入模型需放在 `resources/models/bge-small-zh-v1.5/`（transformers.js 兼容格式，约 90 MB）。模型或推理引擎不可用时，检索会**自动降级为纯词法检索**，不阻塞其它功能。
> `dist:win` 的产物含该模型（约 340 MB）；**CI 构建的安装包不含模型**（模型未入库），因此正式发布使用本地构建的产物。

## 八、发布说明（维护者）

正式发布流程为：本地 `npm run dist:win` → 通过 GitHub API 创建 Release 并上传**当前版本**的 `XieZhiShu-Setup-<版本>-x64.exe` 与其 `.blockmap`。

> ⚠️ 请**不要**直接推送 `v*` 标签：`.github/workflows/release.yml` 会在 CI 上重新构建，而 CI 产物**不含本地嵌入模型**，会把已发布的安装包覆盖成降级版本。
