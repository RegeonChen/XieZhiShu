# 志书撰写工具（XieZhiShu）

AI 辅助地方志 / 志书编纂的 Windows 桌面工具。围绕「收集 → 整理 → 归纳 → 撰写 → 审校」的修志全流程，把大模型能力嵌入到资料整理、初稿生成、矛盾检测与来源溯源中，全程「依靠不依赖、赋能不替代」，由人工主导考证、篇目、人文内涵与终审。

---

## 一、产品定位

面向地方志编纂业务，解决修志过程中资料庞杂、检索低效、初稿起草耗时、体例规范难统一、来源难追溯等痛点。产品坚持以下原则：

- **本地优先**：所有用户数据保存在本地 SQLite 与本地文件系统，不要求账号，不依赖自有云服务；仅对外调用用户自行配置的大模型与用户提供的信源网址。
- **信源白名单**：AI 撰写时只使用用户导入的文件与用户提供的信源网址，杜绝模型自发获取外部信息、编造出处。
- **全程可溯源**：AI 输出的每个片段都标注来源，可回溯到原文位置。
- **人机协同**：矛盾裁定、事件补充、文段修改、终审定稿均由人工主导，AI 仅提供初稿与提示。

## 二、功能介绍

### 1. 配置大模型

在「设置」页配置 LLM Provider（API 地址、模型、密钥），内置常用预设模型，可一键切换当前使用的模型；密钥本地加密存储。

### 2. 工作区资料库

将本地文件夹指定为资料库，双向实时同步：文件新增 / 变更自动解析入库（PDF、DOCX、XLSX、图片 OCR 等），移动 / 重命名不丢失标签、摘要等元数据，删除走系统回收站可反悔。支持标签管理与多选筛选。

### 3. 网页资料库

注册信源网址后，每次生成初稿时自动检索该网站中与撰写要求相关的文章并抓取正文，与本地文件同等参与资料粗筛、矛盾检测与来源溯源。

### 4. 写作规范（Skills）

固化志书写作规范：通用规范默认注入所有生成，部类细则按小节标题智能匹配注入。预设规范可修改，也可自建，生成初稿时自动带入相应规范。

### 5. 撰写任务与初稿生成

新建撰写任务后，基于资料库 + 写作规范生成初稿；支持多轮对话式修改、逐片段来源标注、生成进度提示，撰写对话与进度状态在页面切换后保持不丢失。

### 6. 矛盾扫描与裁定

对资料内容自动检测史实矛盾、表述冲突，并以对话框形式呈现给用户人工裁定，裁定结果可回写到初稿。

### 7. 新手引导

首次启动提供分步骤聚光引导，覆盖「配置大模型 → 选择工作区 → 添加网页资料库 → 管理规范 → 新建撰写任务」的核心闭环。

### 8. 诊断日志导出

在设置页一键导出近期交互日志（含按钮点击、大模型交互、资料库变动，以及发送给大模型的提交物内容），便于复现与排查问题。

## 三、技术实现

### 技术栈

- **桌面框架**：Electron + electron-vite
- **前端**：React 18 + TypeScript（strict）+ TipTap（ProseMirror 所见即所得编辑器）
- **本地存储**：better-sqlite3（SQLite）
- **向量嵌入**：`@huggingface/transformers` + 本地 `bge-small-zh-v1.5`（ONNX 模型，纯本地推理，不联网下载模型）
- **推理后端**：onnxruntime-web（WASM）
- **打包**：electron-builder（NSIS，Windows 安装包）
- **测试**：Vitest
- **CI/CD**：GitHub Actions（推送 `v*` 标签自动构建并发布 Windows 安装包）

### 架构说明

采用 Electron 三层结构：

- **主进程（src/main）**：负责窗口管理、SQLite 数据访问、大模型调用、资料解析与索引、文件系统同步、日志。
- **预加载（src/preload）**：通过 contextBridge 暴露类型安全的 IPC 接口。
- **渲染进程（src/renderer）**：React 界面，通过 IPC 与主进程通信。

### 关键实现

- **RAG 检索**：采用「摘要级粗筛 + 过滤式精检」——段落分块 + 字符 bigram 词法打分 + 本地向量余弦检索（词法相关或向量相似度达标的段落全部保留，不做 Top-N 截断）；支持可选的 LLM 摘要索引（「整理资料」手动触发）。
- **LLM 调用健壮性（2026-08-19）**：瞬时故障（429/5xx/网络抖动）自动指数退避重试；生成初稿与自由对话支持 SSE 流式输出，聊天面板实时显示正文/回复。
- **本地嵌入**：`bge-small-zh-v1.5` 在 Electron 主进程中通过 onnxruntime-web 的 WASM 后端加载，`allowRemoteModels=false` 严格本地；为避免 Windows System32 的 `onnxruntime.dll` 与原生绑定版本冲突，`onnxruntime-node` 通过本地 stub 转发到 `onnxruntime-web`。
- **工作区同步**：以 `content_hash`（sha256）+ 文件 `mtime/size` 为映射锚点，chokidar 监听 + 防抖 + 兜底对账，实现文件系统 ↔ 数据库的双向同步。
- **来源溯源**：AI 输出按片段标注来源，可回溯到具体资料与原文。
- **日志系统**：主进程内存环形缓冲，IPC 自动包装记录，敏感字段脱敏，大模型提交物单独缓冲，支持一键导出。

## 四、本地开发

```bash
# 安装依赖
npm install

# 本地开发（启动 Electron + Vite 热更新）
npm run dev

# 类型检查
npm run typecheck

# 运行测试
npm run test

# 构建并打包 Windows 安装包
npm run dist:win
```

> 本地嵌入模型文件需放置在 `resources/models/bge-small-zh-v1.5/`（transformers.js 兼容格式）。模型 / 引擎不可用时，检索会自动降级为纯词法检索，不阻塞其它功能。

## 五、发布

向 `main` 分支提交后，推送 `v*` 标签即可触发 GitHub Actions 自动构建 Windows 安装包并发布 Release：

```bash
git tag v0.1.0
git push origin v0.1.0
```

## 目录结构

```
├── src/
│   ├── main/          # Electron 主进程（db / llm / rag / workspace / writing / import）
│   ├── preload/       # 预加载脚本与类型声明
│   ├── renderer/      # React 渲染进程
│   └── shared/        # 主进程与渲染进程共享的类型与 IPC 契约
├── resources/         # 本地模型等资源
├── vendor/            # 本地 stub 依赖
├── electron.vite.config.ts
└── package.json
```
